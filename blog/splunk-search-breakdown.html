THE EVENT THAT MATTERS

Windows Event ID 4946

Today, one of the events I worked with was Windows Event ID 4946, a new Windows Firewall rule being added.

Why would I care about this as a SOC analyst? Because a firewall rule change needs context.

It could be completely legitimate software behavior. Or it could be something I need to investigate further: an unauthorized application, unexpected remote access, a persistence mechanism, a backdoor, or simply configuration / policy drift.

So instead of just finding the event, I wanted to make that activity visible in my homelab dashboard.

03

THE SPL

My SPL

Instead of stopping at simply finding Event ID 4946, I wanted to make the activity useful inside my homelab.

SPL 
index="mydfir-lab1" host="winvm" EventCode=4946
| stats count by _time, ComputerName, Profile_Changed, Rule_Name, Rule_ID
| sort +_time
Part What it does
index="mydfir-lab1" Searches the Windows data I've ingested into my homelab index.
host="winvm" Narrows the search to my Windows VM.
EventCode=4946 Looks specifically for new Windows Firewall rules being added.
| stats count by ... Gives me a cleaner view of when the change occurred, which machine it happened on, which firewall profile was affected, the rule name, and its unique ID.
| sort +_time Sorts the results chronologically so I can follow the activity over time.
